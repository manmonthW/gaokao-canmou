# 智能匹配算法通俗解读

> 对应实现：`webapp/backend/app/services/match.py`（数据版本 2026.3，覆盖 2024/2025/2026 三年）。
> 本文用通俗语言讲清算法如何工作、三年数据如何被使用；所有阈值与代码 `MATCH_CONFIG` 一致。

---

## 一、先建立一个观念：一切比较的都是"排队位置"（位次）

分数每年含金量不同（题难题易不一样），但**位次**（你在全省排第几名）是稳定的硬通货。所以算法的核心只有一句话：

> 拿你的位次 R，去对比每个"学校+专业"过去三年录取门槛位次，看你站在什么位置。

位次数字**越小越好**（第 3000 名比第 8000 名强）。某专业某年的"门槛位次"= 那年最后一名被投档考生的位次，比如 8000，意思是"那年排到 8000 名以内的人才进得了档"。

## 二、第一步：切出"候选单元"，并做三道硬过滤

**单元 = 院校 + 专业 + 批次**（比如"大连理工-计算机-本科批"）。注意：**不按学校聚合**。同一所学校不同专业位次可能差几万名，按校平均会掩盖这种差异，所以以专业为最小单位。

从原始投档数据取数时，三道硬过滤：

1. **类别/学科类/批次严格一致**：你是"普通类·物理·本科批"，就只比这个格子内的数据；
2. **只要"常规"投档，剔除"征集"**：征集是补录，门槛忽高忽低，会污染参考；
3. **只用"投档最低分"这一口径**：辽宁普通批官方只发投档线，所以统一用它代表进档门槛。

另外有个跨年小处理：2026 年把"本科提前批"拆成了 A/B 段，代码里把别名归一，保证 2025 的"本科提前批"和 2026 的 A/B 段被合并成**同一个单元**，三年数据才接得上。

## 三、第二步：把三年数据压缩成 5 个数字

每个单元把 2024/2025/2026 三年（有哪年算哪年）的门槛位次摆在一起，算出：

| 数字 | 含义 | 例子（三年门槛 8000 / 9500 / 12000） |
|---|---|---|
| best（最好/最难年） | 位次数字最小那年 = 历史上**最难**进的一年 | 8000 |
| worst（最宽松年） | 位次数字最大那年 = 最容易进的一年 | 12000 |
| median（中位） | 中间水平 | 9500 |
| span（跨度） | worst − best，衡量波动 | 4000 |
| last_year_rank | 最近一年（2026）的门槛 | 12000 |

**关键点：三年数据不是取平均，而是取"区间"。** 平均数会掩盖"大小年"，而区间 [8000, 12000] 告诉你的是"明年门槛大概率在这个带子里移动"。分档的本质就是：**你站在这个带子的哪个位置**。

## 四、第三步：分档（核心逻辑，配例子秒懂）

先画一条**安全线 = best × 0.85**。继续上面的例子：best=8000 → 安全线=6800。

| 你的位次 R | 判定 | 通俗解释 |
|---|---|---|
| R ≤ 6800（安全线） | **保** | 你比"历史最难年"还领先 15% 以上，明年就算门槛收紧也大概率够得着你 |
| 6800 < R ≤ 8000 | **稳** | 你比最难年强，但领先不到 15%，这点领先可能被年际波动吃掉 |
| 8000 < R ≤ 9500（中位） | **稳** | 你落在历史区间内偏强的一半，明年门槛在带子里移动时机会较大 |
| 9500 < R ≤ 12000 | **冲** | 你落在区间内偏弱的一半，需要明年是"宽松年"才进得去 |
| R > 12000 | **冲**（高风险） | 你比历史最宽松年还差，只有门槛大幅放宽才有戏 |

两个"插队规则"：

- **高波动优先**：如果这个单元跨度太大（相对波动 ≥50% 且绝对跨度 ≥2000 名），说明门槛上蹿下跳，直接单独归入"高波动"档，不参与冲稳保——因为历史规律本身不可信。
- **数据不足**：三年里一位次都没有 → "数据不足"（降级为分数参考）；只有 1 年 → 仍分类但明确标注"参考性有限"；**至少 2 年**才算数（`min_years=2`）。

还有两个贴心的"补刀提示"：

- **断崖提示**：如果最近一年门槛（12000）比最难年（8000）宽松超过 30%，系统会追加一句"去年宽松不代表明年"，解释为什么你看起来领先很多却只判"稳"不判"保"；
- **断档检测**：如果 worst > 中位 × 1.6，说明某年出现过断档（没人报、门槛暴跌），提示历史参考性下降。

### 0.85 这个数是哪来的？——回测定的

不是拍脑袋：拿 2025→2026 真实数据做回测，统计"明年门槛相对今年最难年收紧多少"，发现 90% 的情况下收紧不超过 13%（P10≈0.87）。所以把安全边际定在 0.85（留 15% 缓冲），回测验证：判成"保"的单元，次年规则仍成立的比例为**物理 91.6% / 历史 92.4%**（2024→2025 是 92.1%/93.3%，本科批+专科批共 6 组回测）。这个数写死在配置里，**改它必须重跑回测附报告**，这是制度。

## 五、"保"档内部再分三小档（防止浪费志愿槽位）

辽宁有 112 个志愿，保底不是越深越好：

| 子档 | 条件 | 含义 |
|---|---|---|
| 标准保底 | best ≤ 1.5×R | 主力保底带，保护够且真会去读 |
| 极稳垫底 | 1.5R < best ≤ 3R | 少量垫底用 |
| 过深保底 | best > 3R | 标记 over_safe：保护在 2 倍左右就饱和了，再深不增加安全性，纯浪费槽位 |

对称地，"冲"档里如果历史门槛比你好超过 20%（best < 0.8R），标记"超冲"——基本只消耗槽位，建议当梦想位。

## 六、三年数据到底各自贡献了什么（总结）

- **三年合起来** → 区间 [best, worst] + 中位 + 跨度：决定你站在带子的哪个位置（分档依据）；
- **最难年 best** → 画安全线（保档判据）；
- **最近年** → ① 同档内排序用"和你位次的接近度"；② 断崖提示（去年宽松不作数）；
- **年份数** → <2 年标"数据不足"；worst 异常大 → 断档警示；
- **最近两个数据年都有位次**（has_both_years）→ 一个可选筛选项，且口径自动取"当前库里最大的两个年份"，明年接入新一年数据不用改代码。

## 七、分档之外的几层防护

1. **选科校验**：用 2027 官方选科表。首选科目不符 → 直接排除（硬约束）；再选科目不符（且你填了再选）→ 排除；官方表没收录的 → **不排除但挂"未核验"警示**（保守优先，因为计划可能调整）。校名对不上的还有人工核对过的别名表兜底。
2. **排序**：先按 保→稳→冲→高波动→数据不足 分档；**同档内按 |你的位次 − 最近年门槛| 升序**，即"最接近你的排最前"——保档里排第一的是"最好的保底"而不是"最深的垫底"。可切换"院校层次优先/城市优先"，接近度退为次键。
3. **敏感度试算**：一键看位次 ±5%/±10% 时各档数量怎么变，让你知道边界是否敏感。
4. **位次区间模式**（备考期估位）：给区间时，用**悲观端**做主判定、乐观端并列展示，保守优先。
5. **覆盖曲线分年视图**：工作台整表覆盖曲线默认按「最难年」门槛绘制（分档基准），可切换查看 2024/2025/2026 任一年的门槛曲线（当年无数据的志愿画空心点），或「三年叠加」对比年际跳动；切换只改纵轴口径，**不改变分档**——分档仍以最难年+安全边际为准。方案快照在加入时冻结，年度接入前建的旧方案缺新年数据时，工作台会提示并可用「刷新到最新数据」一键重算。

## 八、它"不做什么"（同样重要）

- **不算录取概率**：分档是"对明年门槛落在哪个区间的判断"，不是概率预测，所有解释文案都用区间语言；
- 不用征集数据、不按校聚合、不用平均分；
- 偏好筛选（省市/层次/性质/专业关键词）只影响展示，不改分档。

---

**一句话总结**：算法把每个"学校+专业"过去三年的门槛位次压成一个区间 [最难, 最宽]，用回测固化的 0.85 安全边际在最难年外面再画一条安全线，然后看你站在这条线和区间的哪个位置——安全线内是"保"，区间内偏强是"稳"，区间内偏弱或更差是"冲"，跨度太大是"高波动"，年份不够是"数据不足"；三年数据的价值在于给出"明年门槛可能的移动带"，而不是某一个平均数。
