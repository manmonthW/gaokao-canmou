## 二、P1：备考期双模式（位次区间 + 线差法估位）

**P1a 区间匹配**（`backend/app/services/match.py` + `routers/match.py`）：

- `/api/v1/match` 新增 `rank_lo`/`rank_hi`（与精确 `rank` 三选一，同给 lo/hi 启用区间模式）；
- 分档以**悲观位（rank_hi，更差）**为主判定（`risk`、`totals`），
  同时以乐观位（rank_lo）重算一遍，输出 `totals_lo` 与逐条 `risk_lo`；
- 两档不一致的候选前端标「乐观」角标，把不确定性前置而不是藏起来。

**P1b 线差法估位**（`backend/app/services/locate.py`）：

- `GET /api/v1/locate/estimate-rank`：模考分 − 模考线 = 线差 →
  用 `batch_control_line` 换算历史同年「省控线 + 线差」对应分数 →
  `score_rank` 反查位次；对 2025/2026 各算一次，取并集后**外扩 ±10%**
  输出 `suggested_interval`；响应自带醒目 `note`（估算非真实位次）。
- 数据全部现成，零新表。

**P1c 前端**：

- `useProfile.ts` 档案支持 `rank_mode: exact | interval`（rank_lo/rank_hi）；
- `Locate.vue` 新增「模考估位」工具卡（输入模考分+模考线 → 建议区间一键写入档案）；
- `Match.vue` 区间模式：档案条显示「估计位次 lo–hi」，结果头部并排两组分档计数
  （悲观为主、乐观为次），逐行显示乐观档差异；敏感度试算以悲观位为基准。

## 三、P2：志愿表升级为一等公民（Workbench）

- **P2a 覆盖曲线**：工作台方案视图新增 SVG 整表曲线——横轴志愿序号、
  纵轴该位志愿快照的历史门槛位次（数值越小越好 → 曲线应单调向下）；
  叠加考生位次水平线（区间档案画两条）。一眼看出单调性、保底深度、断层。
  视觉增强版：Catmull-Rom 平滑曲线 + 主色渐变面积填充、考生位次线上下
  「冲击区/保底区」分区着色、四档横向网格刻度 + 横轴序号刻度、
  档位着色圆点（白描边、悬停放大）、图例行与阅读提示。
  **尺度修正（第一性原理）**：线性绝对位次轴会把冲/稳压扁在顶部同一行
  （位次是比值尺度），故 y 轴改为 **log₁₀(门槛位次)**：冲在虚线上方、
  稳紧贴线下、保沉底，三档天然分层；刻度改 1/2/5×10^k（≥1万显「N万」）；
  新增「稳档带 · 最可能录取区间」高亮横带（你的位次线→稳簇底部）。
- **P2b 逐位校验**：`usePlanner.analyzePlan` 从「计数提醒」升级为「位置规则」：
  尾部保底（最后 max(3, ceil(总数×20%)) 位必须全为保）、
  位次倒挂（后一位门槛好于前一位）、断层（后一位门槛 > 前一位 × 2.5），
  提醒文案统一引导「按冲→稳→保重排」。
- **P2c 梯度模板**：候选池 ≥3 时一键生成空表模板——总数 min(112, 池大小)，
  冲 30% / 稳 40% / 保 30%，各档内按门槛位次升序自动形成梯度方向。

## 四、P3：匿名优先

- `router/index.ts`：删除强制登录守卫（查询/定位/匹配/工作台全程匿名可用），
  守卫仅保留公开页（登录/注册）对已登录用户的跳转；
- `useAuth.ts`：无 token 时**保留** localStorage 数据（原来会清掉）；
  登录时云端为空则把本地数据上推合并；恢复会话时云端为空同样上推；
  登出清空本地（共享设备安全）；
- `App.vue`：匿名时也显示完整应用壳（原 `chromeless` 会整体隐藏界面），
  登录按钮带 tooltip「不登录也能用：数据只存本机浏览器」。

## 五、P4：结果反馈闭环

**架构决策（与原计划的偏差）**：反馈数据**不**做 PG 迁移（原 todo 写 0013），
原因是 `gaokao_web_ro` 是严格只读账号（config.py 校验 DSN、迁移仅授 SELECT），
分析库写入会破坏「只读查询」边界。改存 **SQLite 用户库**（`app/user_db.py`），
`init_db()` 幂等建表，重启自动生效，零迁移。

- 表 `outcome_feedback`：考生年份/类别/科类/批次/位次/方案总数 +
  outcome（admitted/slipped/unknown）+ 录取志愿序号/档位/院校/专业 + 备注；
  `user_id` 可空（匿名提交），外键 ON DELETE SET NULL。
- `POST /api/v1/feedback`（匿名可用，`optional_user` 依赖）：
  校验 outcome 合法、admitted 必须给序号、序号 ≤ 方案总数、档位合法；
  `GET /api/v1/feedback/summary`：总量 / 按结果 / 按录取档位的匿名汇总。
- 工作台工具栏「回填录取结果」入口：自愿弹窗，提交时携带所选志愿条目的
  档位/院校/专业快照——这是系统的**第一个真实标签集**，直接支撑
  分档阈值校准与「概率化展示是否可行」的判断。

## 十一、冲稳保算法重规划：边界治理 + 策略配比（2026-08-08 追加）

依据 `docs/strategy-chong-wen-bao.md`（张雪峰及多家机构经验）与回测数据，
从考生报考实际出发重新审视分档：原算法保档只有下限（0.85 边际）无上限、
冲档无上界，导致 R=1,355 时保池 1.2 万条深至 13.6 万位、清华也标「冲」。

**第一性原理结论**：
- 滑档保护在 best≈2R 处饱和（回测：门槛需年际改善 >100% 才失守，
  而变动 P90≈31%、≥50% 仅 4.7%）；再深不增加安全性，只消耗 112 志愿配额；
- 行业共识保底 ~35% 恒定（防滑档靠深度×数量两者），冲的比例取决于风险偏好；
- 行业「稳=±5%」窄带与回测波动矛盾，**不采纳**（保留区间法）。

**后端**（`app/services/match.py`）：
- `MATCH_CONFIG` 新增 `safe_band_core: 1.5`、`over_safe_ratio: 3`、
  `over_reach_ratio: 0.8`；
- 新增 `_over_safe/_over_reach/_safe_band`；候选项新增 `over_safe`、
  `over_reach`、`safe_band`（标准保底 ≤1.5R / 极稳垫底 ≤3R / 过深保底 >3R）
  三字段与「保护已饱和/差距过大」依据文案；五档资格判定与
  `safe_margin=0.85` 不变（标记属展示/策略层，向后兼容）。

**前端**：
- 匹配页：保档行显示子档标签（标准保底/极稳垫底/保底过深），冲档行超冲标签；
- 方案新增 `strategy`（冲击 36/29/35、均衡 20/50/30、稳妥 10/55/35，默认均衡），
  工作台可切换；体检新增配比校验（保底低于基线-10pp 或冲超出基线+15pp 告警）
  与过深保底/超冲警告；
- 梯度模板按所选策略基线生成，保池剔除过深、冲池剔除超冲；
- 覆盖曲线：过深点半透明、超冲点虚线描边，悬停文案标注。

**验证**：pytest 35 过（新增 3：子档分段/过深/超冲边界）；冒烟示例：
福建商学院 best=107,575 → 过深保底（R_hi×3=39,000）；
首都医科大学 best=1,183 → 超冲（R_hi×0.8=10,400）。

## 十二、同档排序修正：最接近匹配原则（2026-08-08 追加）

**问题**：`_pref_sort_key` 用带符号 `diff = R − last_year_rank` 升序，
保档 diff 恒负 → 最深的垫底校排最前（12 万位保底占据保 tab 首页），
最好的保底（best≈R/0.85 带）被压到第 200 页后；level/city 偏好模式同坑。

**修正**（`app/services/match.py._pref_sort_key`）：同档次键改为
**接近度 |diff|**（不带符号）：
- certainty（默认）＝(档位, |diff|, 院校层次, diff)：同档内门槛最贴近你位次的
  单元靠前（保档＝最好的保底，冲档＝最现实的冲刺），同距离时 985>211>双一流；
- level＝(档位, 院校层次, |diff|)；city＝(档位, 城市分级, |diff|)。

**验证**：pytest 36 过（新增 `test_pref_sort_certainty_nearest_first`：
保档浅先于深、冲档近先于远、同距离层次高者先、偏好模式次键同用接近度）；
冒烟新增断言：certainty 序列 |diff| 非递减、保池首页无 over_safe。
实测：保 tab 首页从 12 万位垫底校 → 北京化工大学（best=15,441，最浅保底）；
过深项（沈阳城市学院 best=114,346）沉到保池尾部；超冲项（西安交通大学
best=635）在冲区尾部。

## 十三、展示基准对齐：曲线/表格挂分档基准（最难年），断崖单元点明（2026-08-08 追加）

**问题**：分档基准是 best（历史最难年门槛），但覆盖曲线 y 轴与匹配表主列
显示 last_year_rank（最近年）→ 两基准打架产生视觉倒挂：保档最好的学校
（如北航中外 best≈1,692）在曲线上高于稳档最差的学校（如中国药科大学
last=2,451），违背「单调下沉」阅读直觉；且「领先 1,096 名却判稳」无法自解释。
实际数据：中国药科大学·药学 best=918 / last=2451——去年断崖变易，
分档从严按最难年是对的（明年若回归难年，1,355 反而在门槛线外），错在展示。

**修正**（纯展示层，`_classify` 语义不动）：
1. 工作台覆盖曲线 y 轴改挂 `best_rank`（分档基准），冲/稳/保恢复天然分层；
   悬停文案「最难年 X / 最近年 Y」双值；轴标题与头部提示同步为「最难年门槛位次（对数）」；
2. 匹配表「近年最低位次（2026）」列改为「最难年 / 最近年位次」双值列
   （顺带消除硬编码年份），tooltip 说明分档从严按最难年；
   工作台对比表同步更名「最近年位次」；
3. 稳档依据文案对断崖单元（last > best×1.3）追加：「最近年门槛明显宽于
   历史最难年，去年宽松不代表明年；若门槛回归难年水平，当前领先将不成立，
   故不能计『保』」——两稳分支共用。

**验证**：pytest 36 过；前端构建干净；冒烟全绿；实测中国药科大学·药学
reason 含断崖注意句（best=918 / last=2451）。
